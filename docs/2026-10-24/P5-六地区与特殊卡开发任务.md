## 5A. 必须遵循的视觉实施顺序（2026-10-24 主创补充）

主创要求：**按照已经完成的阿瑞忒学校社团 Home 的制作方式，直接生成一张包含背景、界面 UI 和全页面布局的游戏概念图，然后在 Godot 中分层还原**。不能只画独立的背景图，最后临时补上功能按钮；更不能把整张 UI 截图当成游戏静态背景，导致文字、按钮和热区无法交互。

### 每一处正式新场景的工序

1. **完整游戏界面概念（1920×1080 母图）**：画面须同时体现可见空间背景、前后景层次、人物/互动对象位置（未定人物仅用合理空位或标注 TEST，不擅自定稿）、菜单/按钮/操作入口、文字展示区域、日期或状态信息（如该场景实际需要）、整体色彩与注意力分配。UI 必须是**概念画面的一部分**，与环境整体设计，而不是事后添加。
2. **主创审查、修改、确认**：提供母图及必要的说明，得到明确批准后再进入正式素材拆分与像素还原。禁止用旧 Home 的 UI 直接生搬硬套，也不要让生成模型发明未确认的新玩法、人物和正式对白。
3. **按母图精准分层**：提取/重新绘制背景、建筑/环境、前景物件、人物位与必要装饰；记录原图尺寸、相对坐标、alpha 及源文件，遵照相同构图与版式复原。**UI 在概念图中有视觉设计，但在运行时以 Godot 实时控件实现**：按钮、悬浮/按下反馈、选中状态、可变文本、热区、日期信息、卡牌和动态内容都要真实可操作。
4. **场景还原与实机审核**：把 Godot 运行截图与批准母图并排比较，验证画面结构、背景裁剪、按钮/文字位置、层级、透明前景遮挡、鼠标/键盘操作、缩放。分别测试 1920×1080 与 1600×900。UI 不应仅“功能能点”但外观与概念完全不同；也不能仅图像相似但热区偏离。
5. **交付证据**：每个新场景保留母图、主创批准状态、分层来源、Godot 实机截图、差异/未完成清单。没有图形环境时只交可验证的工程/占位成果，并明确正式视觉尚待主创审批及实机验收。
